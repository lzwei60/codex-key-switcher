# Codex Key Switcher 使用说明

Codex Key Switcher 是一个用于管理 Codex API Key、供应商、模型别名和本地路由代理的桌面应用。它可以让 Codex 固定连接本地路由地址，再由本应用转发到不同上游供应商和模型。

## 适用平台

- macOS Apple Silicon：使用 `Codex-Key-Switcher-1.0.3-arm64.dmg`
- macOS Intel：使用 `Codex-Key-Switcher-1.0.3-x64.dmg`
- Windows x64：使用 `Codex-Key-Switcher-Setup-1.0.3-x64.exe`
- Linux x64：使用 `Codex-Key-Switcher-1.0.3-x86_64.AppImage` 或 `Codex-Key-Switcher-1.0.3-amd64.deb`

当前安装包未签名、未 notarize。首次安装时 macOS 或 Windows 可能出现安全提示，这是正常现象。

当前稳定版本为 `v1.0.3`。应用内“关于”和“设置 -> 更新”显示的当前版本来自桌面端 `app.getVersion()`。

## 首次使用

1. 安装并启动 Codex Key Switcher。
2. 打开“设置”页面，确认 `Codex 配置目录` 是否正确，默认是 `~/.codex`。
3. 打开“配置列表”，点击“添加配置”。
4. 填写供应商名称、API Key、Base URL、API 格式和模型。
5. 点击模型行里的“检测”，确认模型可用。
6. 保存配置。
7. 如果本地路由已启用，首次添加配置后需要完全退出并重启 Codex。

## 配置供应商

进入“配置列表”后，可以添加、编辑、删除供应商配置。

每个供应商包含：

- 名称：用于在界面和状态栏中识别供应商。
- API Key：只保存在本机应用数据目录中。
- Base URL：上游接口地址。
- API 格式：上游 API 协议。
- 模型别名：Codex 侧看到的模型名称。
- 上游模型：真实请求到上游供应商的模型名称。

保存供应商后，应用会按当前连接模式生成模型 Catalog，并在 `config.toml` 顶层写入 `model_catalog_json`：

- 本地路由模式：Codex UI 使用当前供应商的模型别名，网关再映射到真实上游模型。
- 直连供应商模式：Codex UI 使用真实上游模型名，避免绕过网关后无法请求。
- Catalog 文件放在应用私有数据目录，不会污染 `~/.codex/model-catalogs`。

支持的 API 格式：

- Responses
- Chat Completions
- Anthropic Messages

DeepSeek Chat Completions 推荐配置：

- Base URL：`https://api.deepseek.com`
- API 格式：`Chat Completions`
- 上游模型：例如 `deepseek-v4-pro`、`deepseek-v4-flash`

## 模型检测

新增或编辑模型时，点击“检测”可以验证该模型是否能连通。

页面内只会显示：

- 检测通过
- 检测失败

详细错误会通过右上角全局 Message 提示展示。

新增供应商时，检测模型前必须填写 API Key。编辑已有供应商时，如果不填写 API Key，应用会使用本地已保存的 Key。

## 本地路由

本地路由用于让 Codex 固定连接本机地址，再由 Codex Key Switcher 选择具体供应商和模型。

默认地址：

```text
http://127.0.0.1:3456/v1
```

启用本地路由后，应用会写入 Codex 配置文件，使 Codex 使用本地路由代理。

以下场景需要完全退出并重启 Codex：

- 首次添加供应商配置并启用本地路由。
- 退出应用后重新启用本地路由。
- Codex 当前会话仍在使用旧配置。

切换供应商或模型后，应用会更新 Catalog 和默认模型。Codex 的模型 UI 列表在启动时加载，因此必须完全退出并重新启动 Codex；仅打开新会话不保证刷新模型列表。已有会话不会被自动中断。

## 直连供应商模式

直连供应商模式不会启动本地网关，而是将当前供应商的 Base URL、API Key 和上游模型直接写入 Codex 配置。

直连模式限制：

- 仅支持 Responses 格式供应商。
- Chat Completions 和 Anthropic Messages 供应商必须使用本地路由模式，由本地网关完成协议转换。
- 直连模式不会记录本地请求日志和 Token 统计。
- 在直连模式下通过状态栏切换到 Chat Completions 供应商会被阻止，并显示原因提示。

切换直连供应商或模型后，应用会同时更新直连配置和 Catalog。必须完全退出并重新启动 Codex，才能刷新模型 UI 和直连配置；已有会话不会被自动中断。

## 状态栏菜单

应用是状态栏优先的桌面应用。关闭主窗口不会退出应用，状态栏仍会保留。

状态栏菜单包含：

- 路由地址
- 运行状态
- 当前供应商
- 当前模型
- 供应商切换
- 当前供应商下的模型切换
- 打开主界面
- 启动或停止本地路由
- 退出

点击“退出”时，应用会停止本地路由，并尝试恢复 Codex 原配置。恢复后需要重启 Codex。

## 设置

“设置”页面包含三个标签页。

通用：

- Codex 配置目录：默认 `~/.codex`，也可以手动选择。
- 开机自启：支持 macOS 和 Windows。
- 启动时隐藏窗口：当前主要支持 macOS。
- 语言：中文或 English。
- 外观主题：跟随系统、浅色、深色。

路由：

- 启用本地路由
- 自动启动本地路由
- 监听地址
- 监听端口
- 允许局域网监听
- 故障转移
- 检测端口

更新：

- 检查 GitHub Releases 中的最新版本
- 显示当前版本、最新版本和当前平台
- 打开当前平台匹配的安装包下载链接
- 打开发布说明

当前版本采用手动下载安装更新。由于安装包未签名，macOS 或 Windows 可能在首次运行时显示安全提示。

默认端口为 `3456`。端口范围必须在 `1024` 到 `65535` 之间。

隐私：

- 可关闭本地用量记录。
- 可设置记录保留天数。
- 可设置最大保留记录数。
- 设置保存后会影响后续本地路由请求，不会补写历史数据。

## 统计

“统计”页面展示来自本地路由的真实请求数据。

包含：

- 真实请求数
- 真实消耗 Token
- 成功率
- 平均耗时
- 使用趋势折线图
- 供应商统计
- 模型统计
- 请求日志

只有请求经过本地路由时，统计数据才会记录。

统计不会记录请求正文、响应正文或 API Key。关闭本地用量记录后，新请求不会继续写入本地用量数据库。

## 诊断与恢复

“诊断”页面用于检查和恢复本地路由、Codex 配置和备份状态。

常用操作：

- 重新同步 Codex 配置
- 停用路由并恢复 Codex 原配置
- 准备卸载
- 打开恢复脚本目录
- 复制诊断信息
- 刷新

如果应用异常退出或 Codex 配置没有恢复，可以进入诊断页执行恢复操作。

## 卸载前建议

卸载前建议先进入“诊断”页面，点击“准备卸载”。应用会：

- 停止本地路由
- 恢复 Codex 原配置
- 关闭自动路由相关设置

完成后再删除应用。

## 常见问题

### Codex 请求失败或 502

先检查：

- 本地路由是否运行中。
- 当前供应商是否有可用模型。
- API Key 是否正确。
- Base URL 和 API 格式是否匹配。
- 模型检测是否通过。

如果刚启用本地路由，请完全退出并重启 Codex。

### 关闭窗口后应用还在运行

这是正常行为。关闭窗口只是隐藏主界面，应用仍在状态栏运行。要完全退出，请通过状态栏菜单点击“退出”。

### 退出后为什么提示重启 Codex

退出时应用会停止本地路由并恢复 Codex 原配置。Codex 需要重新读取配置，所以需要完全退出并重启 Codex。

### 安装后首次打开为什么不应该要求输入本机密码

应用首次打开、刷新状态栏和展示配置列表时不会主动解密 API Key，因此正常情况下不应要求输入本机密码。

macOS 可能在真正需要读取本地 Key 时弹出钥匙串授权，例如检测模型、启用直连模式、发送本地网关请求、导出包含 API Key 的配置。若首次打开应用就出现本机密码弹窗，请确认安装的是 `v1.0.0` 或更新版本。

### 从旧版本升级后切换供应商提示缺少本地 API Key

`v1.0.0` 会在真正使用 Key 时自动兼容旧版本的 Key 存储格式。若仍然提示缺少本地 API Key，通常说明本机安全存储无法解密旧 Key，或者迁移应用数据时没有迁移系统凭据。此时需要进入编辑流程重新填写 API Key 并保存。
