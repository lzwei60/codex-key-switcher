# Codex Key Switcher 使用说明

Codex Key Switcher 是一个用于管理 Codex API Key、供应商、模型别名和本地路由代理的桌面应用。它可以让 Codex 固定连接本地路由地址，再由本应用转发到不同上游供应商和模型。

## 适用平台

- macOS Apple Silicon：使用 `Codex Key Switcher-0.1.0-arm64.dmg`
- macOS Intel：使用 `Codex Key Switcher-0.1.0-x64.dmg`
- Windows x64：使用 `Codex Key Switcher-0.1.0-x64.exe`

当前安装包未签名、未 notarize。首次安装时 macOS 或 Windows 可能出现安全提示，这是正常现象。

## 首次使用

1. 安装并启动 Codex Key Switcher。
2. 打开“设置”页面，确认 `Codex 配置目录` 是否正确，默认是 `~/.codex`。
3. 打开“配置列表”，点击“添加配置”。
4. 填写供应商名称、API Key、Base URL、API 格式和模型。
5. 点击模型行里的“检测”，确认模型可用。
6. 保存配置。
7. 如果本地路由已启用，首次添加配置后需要重启 Codex，或关闭当前 Codex 会话后打开新会话。

## 配置供应商

进入“配置列表”后，可以添加、编辑、删除供应商配置。

每个供应商包含：

- 名称：用于在界面和状态栏中识别供应商。
- API Key：只保存在本机应用数据目录中。
- Base URL：上游接口地址。
- API 格式：上游 API 协议。
- 模型别名：Codex 侧看到的模型名称。
- 上游模型：真实请求到上游供应商的模型名称。

支持的 API 格式：

- Responses
- Chat Completions
- Anthropic Messages

DeepSeek Chat Completions 推荐配置：

- Base URL：`https://api.deepseek.com`
- API 格式：`Chat Completions`
- 上游模型：例如 `deepseek-v4-pro`、`deepseek-v4-flash`

## 模型检测

新增或编辑模型时，点击“检测”可以验证该模型是否能连通。

页面内只会显示：

- 检测通过
- 检测失败

详细错误会通过右上角全局 Message 提示展示。

新增供应商时，检测模型前必须填写 API Key。编辑已有供应商时，如果不填写 API Key，应用会使用本地已保存的 Key。

## 本地路由

本地路由用于让 Codex 固定连接本机地址，再由 Codex Key Switcher 选择具体供应商和模型。

默认地址：

```text
http://127.0.0.1:3456/v1
```

启用本地路由后，应用会写入 Codex 配置文件，使 Codex 使用本地路由代理。

以下场景需要重启 Codex，或关闭当前会话后打开新会话：

- 首次添加供应商配置并启用本地路由。
- 退出应用后重新启用本地路由。
- Codex 当前会话仍在使用旧配置。

切换供应商或模型后，应用会提示建议打开新会话。已有会话可能继续使用旧上下文。

## 状态栏菜单

应用是状态栏优先的桌面应用。关闭主窗口不会退出应用，状态栏仍会保留。

状态栏菜单包含：

- 路由地址
- 运行状态
- 当前供应商
- 当前模型
- 供应商切换
- 当前供应商下的模型切换
- 打开主界面
- 启动或停止本地路由
- 退出

点击“退出”时，应用会停止本地路由，并尝试恢复 Codex 原配置。恢复后需要重启 Codex 或打开新会话。

## 设置

“设置”页面包含两个标签页。

通用：

- Codex 配置目录：默认 `~/.codex`，也可以手动选择。
- 开机自启：支持 macOS 和 Windows。
- 启动时隐藏窗口：当前主要支持 macOS。
- 语言：中文或 English。
- 外观主题：跟随系统、浅色、深色。

路由：

- 启用本地路由
- 自动启动本地路由
- 监听地址
- 监听端口
- 允许局域网监听
- 故障转移
- 检测端口

默认端口为 `3456`。端口范围必须在 `1024` 到 `65535` 之间。

## 统计

“统计”页面展示来自本地路由的真实请求数据。

包含：

- 真实请求数
- 真实消耗 Token
- 成功率
- 平均耗时
- 使用趋势折线图
- 供应商统计
- 模型统计
- 请求日志

只有请求经过本地路由时，统计数据才会记录。

## 诊断与恢复

“诊断”页面用于检查和恢复本地路由、Codex 配置和备份状态。

常用操作：

- 重新同步 Codex 配置
- 停用路由并恢复 Codex 原配置
- 准备卸载
- 打开恢复脚本目录
- 复制诊断信息
- 刷新

如果应用异常退出或 Codex 配置没有恢复，可以进入诊断页执行恢复操作。

## 卸载前建议

卸载前建议先进入“诊断”页面，点击“准备卸载”。应用会：

- 停止本地路由
- 恢复 Codex 原配置
- 关闭自动路由相关设置

完成后再删除应用。

## 常见问题

### Codex 请求失败或 502

先检查：

- 本地路由是否运行中。
- 当前供应商是否有可用模型。
- API Key 是否正确。
- Base URL 和 API 格式是否匹配。
- 模型检测是否通过。

如果刚启用本地路由，请重启 Codex 或打开新会话。

### 关闭窗口后应用还在运行

这是正常行为。关闭窗口只是隐藏主界面，应用仍在状态栏运行。要完全退出，请通过状态栏菜单点击“退出”。

### 退出后为什么提示重启 Codex

退出时应用会停止本地路由并恢复 Codex 原配置。Codex 需要重新读取配置，所以需要重启 Codex 或打开新会话。
